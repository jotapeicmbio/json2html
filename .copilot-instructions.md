# json2html Library - AI Agent Instructions

## Project Overview

The `json2html` library is a PHP library developed by ICMBio for converting JSON/Array data structures into flexible HTML tables. It's particularly designed for environmental and biodiversity data visualization.

## Key Architecture Patterns

### Strategy Pattern Implementation
- **AbstractRenderer**: Base class for rendering strategies
- **HorizontalRenderer**: Traditional table layout (headers at top)
- **VerticalRenderer**: Vertical layout (headers as first column)
- **RenderTable**: Main facade class implementing the strategy pattern

## Core Development Rules

### 1. Code Standards
- **PHP 8.1+** required
- **PSR-4** autoloading: `Icmbio\Json2html\`
- **PSR-12** coding standards
- **Strict types**: All PHP files must start with `declare(strict_types=1);`
- **100% test coverage** target

### 2. Architecture Principles
- **Strategy Pattern**: Use renderer classes for different orientations
- **Fluent API**: All configuration methods return `self`
- **Immutable rendering**: `render()` method doesn't modify object state
- **Nested table support**: Automatic handling of multidimensional arrays
- **Business rules first**: Read `BUSINESS_RULES.md` before changing rendering behavior or rewriting tests

### 3. Testing Requirements
- **PHPUnit 10.5+** with PHP 8+ attributes (`#[Test]`)
- **Real-world test data**: Use ICMBio biodiversity monitoring scenarios
- **Regression tests**: Maintain backward compatibility
- **Edge cases**: Empty arrays, malformed data, deeply nested structures

## Common Development Tasks

### Aligning Rendering Behavior
1. Read `BUSINESS_RULES.md` first
2. Separate current behavior from desired behavior
3. Treat changes in nested rendering semantics as contract changes
4. Do not update tests to match a new interpretation before the business rule is explicit
5. When behavior differs between horizontal and vertical, document the distinction before coding

### Adding New Renderers
1. Extend `AbstractRenderer`
2. Implement `render(array $headers, array $data): DOMElement`
3. Add to `TableOrientation` enum if needed
4. Update `RenderTable::updateRenderer()` match statement
5. Add comprehensive tests

### Adding New Attributes
1. Add method to `RenderTableInterface`
2. Implement in `RenderTable` following fluent API pattern
3. Store in `$attributes['root']` or `$attributes['nested']` arrays
4. Update both renderer classes to apply attributes
5. Add tests for both root-only and nested scenarios

### Handling Test Data
- Use realistic ICMBio scenarios (biodiversity monitoring, species data)
- Test with Portuguese field names and scientific nomenclature
- Include geographic data (coordinates, areas)
- Test hierarchical structures (monitors → observations → species)

## API Usage Patterns

### Basic Usage
```php
use Icmbio\Json2html\RenderTable;

$table = new RenderTable($data);
echo $table->render();
```

### Advanced Configuration
```php
use Icmbio\Json2html\{RenderTable, TableOrientation};

$table = (new RenderTable($data))
    ->config(['orientation' => TableOrientation::VERTICAL])
    ->tableClass('table table-bordered')
    ->tableId('biodiversity-report')
    ->tableBorder(1)
    ->render();
```

### Nested Table Control
```php
// Apply class to all tables (default for classes)
->tableClass('table', nested: true)

// Apply ID only to root table (default for IDs) 
->tableId('main-table', nested: false)
```

## Troubleshooting Guide

### Common Issues
1. **Namespace issues**: Ensure PSR-4 autoloading is correct
2. **Docker problems**: Check if containers are running with `docker ps`
3. **Test failures**: Verify PHP version compatibility (8.1+)
4. **Memory issues**: Large nested arrays may need memory limit adjustments

### Debug Strategies
- Use `var_dump()` on `$this->dom->saveHTML()` to inspect generated HTML
- Check `$this->attributes` array contents for attribute application issues
- Verify test expectations with actual HTML output formatting
